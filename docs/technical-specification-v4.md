# Integrated AI Math Tutor — 技術仕様書 V4.0

作成日：2026-11-05  
基準：技術仕様書 V3（Tutor / Organizer / Progress Analysis AI、演習と学習記録の統合）およびV4改善指示  
対象：プロダクトの目標仕様と、このリポジトリに含むV4デモの実装範囲

## 1. 目的と設計原則

数学の問いを起点に、説明を読む、数式を扱う、試行する、概念の関係を調べる活動を一つの学習環境で支援する。固定ルートや学年別の一本道を強制せず、学習者が探索先・表示形式・説明量を選択する。サンプルの6トピックは将来の対応範囲を限定しない。

V3の「Board + Explanation」を、複数要素を操作できるBoard中心のワークスペースへ発展させる。TutorはそのBoard上で呼び出す補助パネルとする。講義的な説明と対話を往復できるようにし、AIがユーザーの配置や作業を勝手に置き換えない。

- 機能名をそのまま見出し・リンクに用いる。広告的コピー、比喩的な導線、装飾的な長文は置かない。
- 文字の読みやすさ、操作の発見しやすさ、保存状態、キーボード操作を優先する。
- UI言語と教材・会話の言語を分離する。言語切替で答案や学習記録を翻訳・改変しない。
- 学習記録、AIの解釈、ユーザーによる訂正を区別する。
- 未接続機能を実行済みのように見せない。特にデモ応答、固定解照合、AI採点を区別する。

## 2. 情報設計と共通UI

| ページ                                  | 役割             | 主な操作                                         |
| --------------------------------------- | ---------------- | ------------------------------------------------ |
| 学習ワークスペース / Learning workspace | BoardとTutor     | 要素追加・編集・配置、質問、関連トピックへの移動 |
| 演習 / Practice                         | 問題リスト       | 複数問題を一覧、問題別の入力・ヒント・提出       |
| Knowledge Map                           | 概念の整理       | Graph / Tree、検索、詳細、保存                   |
| 学習記録 / Learning progress            | 履歴と分析       | 試行、元の答案、根拠、訂正、任意の追加学習       |
| 設定 / Settings                         | 表示・データ管理 | 説明量、分析許可、エクスポート、削除             |

サイドバーには4ページと設定を置き、折り畳みボタンを設ける。デスクトップで折り畳むとアイコンを残し、狭い画面ではメニューを隠して作業領域を確保する。どちらも展開操作は常に利用できる。アイコンリンクにもアクセシブルな名称を付け、選択中のページと展開状態を伝える。状態はブラウザに保存する。

関連ページへのリンクは「Tutor」「演習」「マップ」などとする。「考え方を整理したくなったら」のような誘導文を使わない。`topicId`を引き継ぎ、演習では対応する問題位置へ移動する。一覧そのものは維持する。履歴の記録に存在しない理解度や到達度を表示しない。

## 3. 学習ワークスペース

### 3.1 Board

目標はMiro型の拡張可能な二次元キャンバス。各要素は独立したID、種類、位置、サイズ、関連トピックを持つ。

- 要素種類：概念・定義、数式、説明、ノート、例題、図・グラフ、演習参照。初期デモは概念カードとノート。
- 複数要素を同時表示し、追加・削除・移動・サイズ変更ができる。
- マウス／タッチ操作に加えてキーボードでも配置を変更できる。ドラッグ以外の操作方法を提供する。
- 拡大縮小と画面移動で広い作業領域を扱う。ズーム時も移動量をBoard座標へ換算する。
- 手動で配置・記入した要素をAIが無断で削除、上書き、並べ替えしない。
- 将来の整列、グルーピング、接続線、履歴の取り消し、無限キャンバスは追加段階とする。

**今回の実装**：1800×1200の有限キャンバス、スクロール、50/75/100/125%ズーム、概念・ノートの追加と削除、ポインタ／矢印キーによる移動、320/480pxの幅切替。本文・位置・幅は保存する。キャンバスのスクロール位置とズームはセッション中の表示状態であり、再読み込み時は初期化する。無限キャンバス、手描き、共同編集、Undoは未実装。

### 3.2 Tutorパネル

Boardの操作を続けながら質問できるパネルを重ねて表示する。閉じてもBoard上部から再表示できる。対象トピックを明示的に選べ、質問と応答には同じトピックIDを関連付ける。

今回のパネルはBoard内の右下に固定し、サイズ調整に対応する。トピック別の会話を表示し、直近12メッセージを表示対象とするが保存済みメッセージはエクスポート可能。パネルの移動、ドッキング、位置保存、過去履歴のページングは後続段階。

本番のTutorは選択したBoard要素と会話履歴を参照し、説明や演習参照を構造化出力する。ユーザーは「Boardに追加」を選んで提案を適用する。ストリーミング中の取消、失敗時の再試行、送信対象の確認を設ける。デモでは自由入力を保存し、実AIが未接続である旨だけを返す。

## 4. 演習リストと数式入力

### 4.1 リスト構造

問題を一問ずつ切り替える方式から、問題セットの一覧表示へ変更する。各問題は、問題文、数式、解答欄、ヒント、解答例、提出、結果、Tutorリンクを独立して持つ。回答順を強制しない。大規模なセットではページングまたは仮想化を追加し、操作中の解答を失わない。

今回のデモは6題を同時表示する。問題別の下書き、ヒント段階、解答例を閲覧した事実をブラウザに保存する。提出後に修正すると再提出でき、旧答案は別の試行として残す。空白のみの提出と変更のない連続送信を防止する。AIによる出題、問題セット生成・編集、一括提出、絞り込みは後続段階。

### 4.2 数式エディタ

今回の実装はテキスト／LaTeX入力、分数・根号・指数・±・積分の挿入ボタン、KaTeXプレビュー。記号はカーソルまたは選択範囲に挿入する。未完成の数式も入力でき、入力内容を勝手に正規化しない。混合した自然言語答案はテキストとして保持する。プレビューはLaTeX表示の確認用であり、数学的正しさの検証ではない。

将来は視覚的な数式編集、行列、複数行の導出、構造化数式AST、コピー＆ペースト、モバイルの数式キーボードを追加する。視覚エディタを採用しても、テキスト入力と元のLaTeXを保持する。

### 4.3 採点とフィードバック

| 項目               | 今回                       | 本番目標                             |
| ------------------ | -------------------------- | ------------------------------------ |
| 数値・解集合       | 固定問題、限定書式の照合   | 定義域・単位・許容誤差を含む検証     |
| 記号式             | 一般のLaTeX同値判定なし    | パーサとCAS等による決定的検証        |
| 証明・自由記述     | 記録のみ、自動判定なし     | ルーブリックと段階別根拠によるAI講評 |
| 不確かな答案       | 判定なし                   | 判定保留と確認質問、再評価           |
| 解答例閲覧後の試行 | 記録するが正答集計から除外 | 独力の試行と区別して表示             |

本番でもLLMの単独出力を正しさの保証にしない。検証可能な部分は決定的処理で確認し、AIは説明・誤り候補・次の確認事項を提示する。採点結果には採点方法、問題バージョン、モデル／ルーブリックのバージョン、根拠となる答案箇所、不確実性を含める。採点への異議や再試行は元の記録を上書きしない。

ヒントや解答例を開いただけで問題を完了扱いにしない。正答率や試行回数から能力を断定しない。

## 5. Knowledge MapとLearning Progress

V3の共通トピックIDを維持する。Treeの分類構造とGraphの概念間関係は別データとして持ち、両表示で同じノードを参照する。関係には種類、向き、説明、出典または生成根拠を持たせる。サンプル地図は手動作成であり、AI生成済みと表示しない。

Organizer AIは粗い初期マップを補助し、会話からノード・関係・分類変更を**提案**する。重複候補や信頼度を提示し、ユーザーの承認後に反映する。過度な階層化や固定履修ルートを避ける。

Progress Analysis AIは演習記録と許可された会話から傾向の仮説を作成する。観測事実、解釈、根拠、限定条件を分け、ユーザーが訂正・非表示・削除できるようにする。Follow-upは任意の提案として扱い、理由と参照先を示す。今回の分析表示例と関連リンクは固定サンプルであり個別分析ではない。

## 6. 多言語対応

初期対応は日本語と英語。共通ナビゲーション、Board、演習、Map、Progress、設定のUIと静的サンプル教材を切り替える。選択を保存し、HTMLの`lang`も更新する。数式・トピックIDは言語間で共有する。

ユーザーのノート、過去の会話、答案、保存済みのフィードバック原文は変更しない。日付はUI言語に従う。本番ではメッセージキー、複数形、日付／数値形式、翻訳の欠落検査を一元管理する。教材の言語はUI言語と別に選択できる設計にし、原文の数学的意味を変えない。デモの実装は`LocaleProvider`と日英の明示的な文字列対を用いる。

## 7. AI責務とシステム構成

| 論理的なAI役割    | 入力                           | 出力                                | 制約                                   |
| ----------------- | ------------------------------ | ----------------------------------- | -------------------------------------- |
| Tutor             | 質問、選択要素、関連履歴       | 説明、構造化Board要素、演習案、講評 | UIや学習データを直接変更しない         |
| Organizer         | 承認対象の会話要約、既存マップ | ノード・関係・分類の変更提案        | 承認後に適用、既存IDとの重複確認       |
| Progress Analysis | 同意済みの記録・会話、期間     | 根拠付き仮説、任意のFollow-up       | 観測と解釈を分離、ユーザーの訂正を優先 |

3役は論理上の責務分離であり、3つの常駐モデルを必要としない。短い同期処理と非同期の要約・分析を分け、必要なときにだけ実行する。要約・キャッシュ・モデルの使い分け・トークン予算・利用上限でコストを制御する。

現在の構成：Next.js App Router、React、TypeScript、KaTeX、ブラウザ保存。本番は認証済みのサーバーAPI境界、永続DB、ジョブキュー、AI Gatewayを追加する。APIキーはサーバー専用。すべてのAI出力をスキーマで検証し、任意HTML・任意コードとして実行しない。各リクエストにトレースID、モデルバージョン、使用量、状態を関連付ける。

## 8. データ契約（本番目標）

以下は接続段階で実装する契約であり、すべてが現在のデモに存在するわけではない。

| エンティティ     | 主なフィールド                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| Workspace        | id, ownerId, schemaVersion, locale, revision, updatedAt                                         |
| BoardElement     | id, workspaceId, kind, topicIds, x, y, width, height, zIndex, content, source, revision         |
| TutorMessage     | id, sessionId, role, contentBlocks, topicIds, selectedElementIds, locale, createdAt             |
| Topic / Relation | id, localizedLabels, categoryIds / fromId, toId, relationType, explanation, provenance          |
| ExerciseSet      | id, orderedExerciseIds, title, language, version                                                |
| Exercise         | id, version, topicIds, statementBlocks, answerSchema, rubricVersion, hints, solution            |
| AnswerDraft      | exerciseId, exerciseVersion, rawText, latex, mathAst, hintCount, solutionViewed, updatedAt      |
| Attempt          | id, exerciseId, exerciseVersion, answerSnapshot, hintCount, solutionViewed, submittedAt         |
| Assessment       | attemptId, status, method, result, criteria, evidence, uncertainty, modelVersion, rubricVersion |
| Insight          | id, observationRefs, interpretation, confidence, limitations, userCorrection, consentVersion    |
| Proposal         | id, role, proposedChanges, evidenceRefs, status, reviewedAt                                     |

イベントは`eventId`、`schemaVersion`、`workspaceId`、`actor`、`occurredAt`を共通に持つ。提出・採点・提案承認は冪等キーを使い二重処理を防ぐ。手動編集の競合はrevisionで検出し、古いAI結果で新しい答案やBoardを上書きしない。

### デモの保存と互換性

既存の`iamt-demo-v1`を維持し、V3の試行・会話・設定・保存トピックを失わない。新規データは`iamt-board-v4`（カード配列）、`iamt-answer-{topicId}`（version 1の下書き）、`iamt-language`、`iamt-sidebar`に分離する。JSONエクスポートには既存学習データ、Board、下書きを含める。学習データ削除はこれらの学習内容と学習設定を初期化し、UI言語とサイドバーの表示設定は保持する。バックアップのインポートやクラウド移行は未実装。

本番移行時はスキーマバージョン付き移行、整合性検査、ユーザー確認を行う。ブラウザのローカル記録を無断で外部AIやクラウドへ移送しない。

## 9. 非機能要件

- アクセシビリティ：意味のあるHTML、名前付き操作、フォーカス表示、キーボード移動、ズーム時の可読性。スマートフォンではBoard内の横移動とページ全体の横溢れを区別する。
- 信頼性：入力を保持し、保存・通信の失敗を通知する。本番では自動保存の遅延、再試行、競合解決、上限を設ける。
- プライバシー：会話分析とパーソナライズは別設定、初期値オフ。保持期間、削除、エクスポート、送信対象を説明する。学習者の性格・能力を断定しない。
- 安全な描画：会話はテキスト、数式はKaTeXの`trust: false`。生成コードは実行しない。モデルへの指示と教材／ユーザー入力を区別する。
- 性能：大きなBoardや問題リストは表示範囲を絞り、変更の差分を保存する。デモは小規模データ前提で、上限・仮想化・複数端末競合は未対応。
- 運用：エラーを追跡できるが、分析ログへ答案や会話本文を不用意に記録しない。認証・レート制限・課金上限・バックアップを実AI接続前に整備する。

## 10. 実装段階と受入基準

### 今回のV4デモ

1. 複数のBoardカードを追加・編集・移動・幅変更でき、再読み込み後に復元する。
2. Board上のTutorを開閉し、選択トピックで会話を保存する。未接続表示を維持する。
3. 6問題を一覧表示し、独立した下書きと試行を保持する。
4. LaTeX入力とプレビュー、段階的ヒント、解答例、再提出が利用できる。
5. 解答例を見た事実がページ移動後も保持され、正答集計に混入しない。
6. 日英UIを切り替え、サイドバーを折り畳める。設定を復元し、アイコンの名前を失わない。
7. Map → 演習 → TutorでトピックIDを引き継ぐ。
8. JSONにBoardと下書きを含め、データ削除で両方を消去する。
9. デスクトップ／モバイルで全ページに到達でき、ページ全体が横に溢れない。
10. 型検査、単体テスト、production build、ブラウザ操作テストを通す。

### 次段階

- V4.1：Boardの無限領域、Undo、要素の自由サイズ、Tutorの移動と位置保存、構造化数式エディタ、問題セット管理。
- V4.2：認証・永続DB・サーバーAI Gateway、Tutorの生成説明、承認してBoardへ追加、用量制御。
- V4.3：数式検証とAI講評、根拠・ルーブリック・不確実性、Organizerの提案承認。
- V4.4：許可に基づくProgress分析、訂正反映、根拠付きの個別Follow-up。

各段階は順次有効化し、未実装機能を既存UIの実績として扱わない。GitHubへの反映とVercel本番公開は別工程であり、公開先のGit連携・対象ブランチ・ビルド成功を確認して反映を判断する。
